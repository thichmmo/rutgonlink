# Shared-domain HTTPS checks

Run `node scripts/test-shared-domain-https.cjs`. It exercises the actual proxy with real NextRequest/NextResponse and the real shared-domain/site configuration. It covers each allowlisted domain, query bytes and encoded paths **as received by the proxy**, leading `//` path safety, internal origin/port removal, 308 GET/HEAD/POST, edge HTTPS with internal HTTP, missing/malformed scheme metadata, localhost, unknown/custom/lookalike hosts, unchanged main aliases/auth and shared/private API restrictions after upgrade. The same redirect rule applies to Facebook and ordinary browser user agents.

A separate case passes an external query through the installed Next parsed-query reconstruction helpers and `stripInternalSearchParams`, as used before the proxy. It explicitly observes percent/space normalization, then verifies every decoded query value, per-key repeated-value order, empty values and a fully nested signed affiliate URL survive the HTTPS redirect. The direct NextRequest case alone does not model the server adapter and does not establish raw byte preservation from the external HTTP request. Next's default normalization remains enabled; an outer URL signature based on raw query bytes is outside this guarantee.

Authentication is a deterministic fixture; requests use the actual log filter to avoid telemetry, and network access is rejected by the harness. No production record is read/written. These checks prove transport construction and guard preservation, not deployment-edge configuration or Facebook acceptance.
