# Shared-domain HTTPS transport

The proxy upgrades requests on the exact `SHARED_DOMAINS` allowlist and the primary domain to HTTPS when Cloudflare's trusted `cf-visitor` reports `scheme=http`. `GET` and `HEAD` requests use standard `301` so Next.js does not inject `Refresh: 0;url=...` (which Next.js emits only on `308`), while `POST` and other write methods keep method-preserving `308`. Same-host edge HTTP requests to `/robots.txt` and `/.well-known/acme-challenge/*` pass through without an HTTPS redirect so Cloudflare Managed `robots.txt` appends our origin `Allow: /` rules cleanly (instead of returning a corrupted `200` with `Location`/`Refresh` headers and stripped rules) and cPanel AutoSSL HTTP-01 renewals remain reachable. Cloning the request URL prevents a leading `//` path from selecting an external host; Passenger's internal hostname/port never becomes the redirect destination.

This is not a raw external-request byte guarantee inside Next.js. Default Next.js normalization runs before the proxy: it rebuilds parsed query values and the adapter calls `stripInternalSearchParams`. Encoding may change (`%2f` to `%2F`, `%20` to `+`, `~` to `%7E`) and interleaved keys may be grouped, while decoded values and repeated-value order for each key remain intact. A complete signed affiliate URL encoded as a query value retains its inner URL string; stored Shopee/TikTok links are not rewritten by this article-URL redirect.

Existing main-domain canonical behavior and all API/auth restrictions remain intact. `next.config.ts` scopes `X-Frame-Options: DENY` to `/dashboard`, `/admin`, `/login`, `/register`, `/checkout`, and `/api` routes so public `/p7/*` and short-link pages are not frame-blocked during link-shim/preview checks. Request-log telemetry in `proxy.ts` filters bots (`facebookexternalhit`, `Facebot`, `meta-externalagent`, `WhatsApp`) before reading auth tokens and posts only to `buildSiteUrl("/api/internal/log")` when `LOG_SECRET` is configured. While `proxy.ts` intentionally leaves unknown/custom `Host` headers unredirected, `app/[shortCode]/route.ts` upgrades edge HTTP to HTTPS (`301`) once database lookup confirms a verified custom domain.

The original Mesale guard/noscript behavior (`lib/public-post-guard.ts` and `lib/popup-settings.ts`) is untouched. Direct-IP Top-1M shared domains (`6739dd4f.nip.io`, `tin24h-6739dd4f.nip.io`, `103-57-221-79.sslip.io`) upgrade non-Cloudflare `:80` requests via Apache `.htaccess` (`RewriteCond %{HTTP:CF-Visitor} ^$` -> `301`) while keeping `/robots.txt` and `/.well-known/acme-challenge/*` on HTTP for AutoSSL renewals.
