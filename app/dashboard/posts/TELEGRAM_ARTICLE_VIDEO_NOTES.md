# Telegram article video insertion

The quick Telegram input now accepts a public HTTPS article link as well as the existing direct video/iframe inputs. Existing supported inputs stay synchronous; an unrecognized article URL is resolved through the authenticated `/api/content/resolve-video` endpoint. A successful canonical HTTPS MP4/WebM/OGV/OGG source is validated with the existing video parser and inserted once. Remote HTML, metadata and provider iframe results are not inserted. Signed source queries remain intact.

Resolution shows `Đang tìm video...` and uses the parent's media-busy state to block saving until completion. The URL remains editable: editing it, changing the draft body, disabling/closing the editor or unmounting aborts and invalidates the pending result. Errors retain the input and content for retry. Replacement still requires the existing confirmation after a valid video is found; no automatic save occurs. Title, domain, publish flag, popup choice and saved Telegram settings retain their normal form behavior. The shared save label is `Đang xử lý video/ảnh...` for both resolution and uploads.

Verification: `node scripts/test-article-video-ui.cjs` uses the actual TSX editor and PostManager with mocked API responses for direct inputs, exact signed source insertion, errors, race cancellation, replacement, upload/delete continuity, new-draft defaults/manual choices and existing edit identity. Existing quick-form, dashboard and media-removal checks cover the original flow. These deterministic tests do not prove live source extraction or playback; those are verified separately by the coordinating task.

Live check (2026-10-08): the isolated local PostManager form used the actual API/helper against `https://nhieuchuyenduongpho.com/2026/10/07/da-nang-10/`, inserted one `4pk7uGZp1.mp4` source and played it (720×1280, 110.56 seconds, playback advanced to 11.2 seconds without a media error). An article with no video kept its input and the inserted source; individual deletion still worked. Local account/post data were fixtures and no production post was saved. Screenshots and response evidence remain ignored.
